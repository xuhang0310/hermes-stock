# 每日研究闭环与策略进化驾驶舱 · 重新规划 v2

2026-09-19｜老板评审稿｜方案与 ImageGen 静态 UI 原型，尚未实施。

## 1. 本次怎么重新设计

建议建成一个「研究进化中心」，包含两个独立执行的系统和一个共用的证据账本。

| 系统 | 负责什么 | 使用者关心的问题 |
| --- | --- | --- |
| 每日研究执行 | 数据更新、全 A 因子、正式/候选评分、组合核算、到期评价、日报 | 今天跑到哪了？数据可信么？哪些结果可用？哪里要处理？ |
| 候选策略进化 | 提出假设、冻结改动、成本回测、独立验证、同口径比较、保留/淘汰、提交晋级 | 改了什么？证据支持么？比旧方案好在哪、差在哪？是否值得替换？ |
| 证据与决策账本 | 连接实验、版本、每日运行、数据、评价与审批，保留失败历史 | 每个结论能否追到当时的输入、规则、结果和决定？ |

正式方案每天按已冻结的规则执行；较慢的候选回测和独立检验走独立队列，不阻塞正式方案研究。两条线在「新旧对比」和「日报」汇合。正式方案的当日数据不合格时，阻断依赖该数据的新信号和新模拟订单，并生成异常日报。

与上一版相比，本版不把 11 个阶段、全部指标、完整历史和审批表单挤在同一屏。先回答当前页面的核心问题，再进入证据。ImageGen 图仅展示界面与状态；图中按钮不是已经接通的功能，所有数值均为演示数据。

## 2. 三张核心 UI 与使用路径

### 页面一：每日研究台

默认按交易日打开。上方只放交易日、运行编号、总体执行状态、待处理事项和日报入口。

主区域为阶段清单，按「数据与选股」「验证与模拟」「评价与决策」分组。每个阶段显示对象、状态、最近产物、耗时与可操作入口。右侧展示当前阶段详情及异常处理；下方展示 5/20/60 日到期队列和日报状态。

必须区分三种粒度：

- 周期级：这个交易日的研究任务是否执行到日报。
- 方案级：哪个正式、挑战者、影子方案的依赖通过或失败。
- 评价批次级：哪个历史信号已经观察到期，哪个仍在等待。

例：正式方案日常任务完成、一个候选实验失败、另一个 60 日观察仅到 32 日，可以同时成立。不能把所有结果汇总成一个「11/11 验证成功」。

### 页面二：策略进化台

顶部展示当前正式方案、选中挑战者、影子观察数量和待审批数。主体只围绕一个明确候选与当前正式版本比较。

先显示**比较协议**：股票池、日期区间、数据版本、基准、资本、费用及执行模型是否一致。不可比时隐藏改善结论，提供重新生成对照运行入口。

左侧为费用后净值和回撤，右侧为完整指标表；下方为市场阶段稳定性、前瞻成熟度和下一步实验。改善项和退步项都必须可见。准确率只是辅助，不占据主 KPI。

### 页面三：实验档案与人工审批

实验档案默认不遮挡内容：唯一编号、父实验、假设、改动前后、修改理由、版本清单、时间线、判断与证据、完整成功失败历史。只有点击「审查晋级」才展开审批抽屉。

抽屉顺序为：新旧方案 → 门槛明细 → 改善及不利证据 → 生效时间与回退方案 → 确认项与审批意见。未通过门槛或证据不成熟时，确认入口禁用并写明原因。

辅助页面为证据库、模拟组合和研究日报。它们复用相同的实验与运行编号，不另建孤立的数据岛。

## 3. 三个独立状态体系

| 状态类别 | 示例 | 不能推断的结论 |
| --- | --- | --- |
| 任务执行状态 | 排队、运行、完成、阻断、失败、已复用 | 回测任务完成不意味着策略有效 |
| 研究证据状态 | 支持、不支持、未到期、证据不足、已失效 | 样本不足不等于失败，等待到期不等于系统卡住 |
| 方案治理状态 | 草案、挑战者、影子、待审批、正式、暂停、退役 | 算法验证通过不代表可以自动成为正式方案 |

界面使用状态文字与符号，不只靠颜色。研究结论的「改善/退步」与股票涨跌色独立；回撤从 −10% 变为 −12% 必须显示退步。

## 4. 每天具体执行哪些工作

时间均为 Asia/Shanghai。以交易日历和数据完成情况为准，不以固定时钟代替数据可用性。

| 步骤 | 每日动作 | 可查产物 | 失败或未完成怎么办 |
| --- | --- | --- | --- |
| 1 数据更新与质检 | 拉取增量并检查日线、每日指标、交易状态、公司行动、股票池及因子所需资料 | 数据快照、可见时间、覆盖清单、质量报告 | 缺失、陈旧或单位错误显式阻断依赖项，不用昨日数据冒充当日成功 |
| 2 全 A 因子计算 | 对全部应覆盖 A 股处理已登记因子，增量计算和版本化处理 | 因子截面、参数、缺值原因、处理代码版本 | 单因子失败只阻断依赖它的方案；全 A 覆盖台账包括不可用股票 |
| 3 自动选股 | 在同一数据快照上运行正式、挑战者和影子 | 评分、排名、约束、目标股票池 | 保存入选、合格未入选、不合格三类，不只保存赢家 |
| 4 入选和排除分析 | 确定性规则生成原因，模型按证据解释 | 因子贡献、规则触发、证据 ID、解释版本 | LLM 失败可以降级为规则解释，不改写排名和数值 |
| 5 成本化回测 | 新配置、新代码、新协议或变更输入才重算；其余复用带哈希的证据 | 净值、成交/未成交、成本分解、资金约束 | 日线无法支持的成交假设标低可信或阻断晋级 |
| 6 独立样本外验证 | 冻结方案进入受控验证队列；每天检查新结果与待执行任务 | 预登记协议、时间切分、标签隔离、封存测试和统计报告 | 不每天重新打开同一留出集调参；已用于优化的区间不能继续叫独立测试 |
| 7 模拟组合更新 | 核算已发生的模拟成交与持仓，并生成下一可交易时段的目标单 | 策略独立账户、订单、成交、现金、仓位与净值 | 部分成交、拒单、延期、陈旧估值都有记录；不影响个人手工模拟账户 |
| 8 5/20/60 日评价 | 处理过去信号中已到期的批次，同时更新连续组合指标 | 到期任务、观察天数、收益和质量、不可用原因 | 新实验不能当日获得真实 60 日结果，未成熟数值留空 |
| 9 新旧方案比较 | 对同协议的正式与候选运行生成对照 | 改善、退步、样本量、区间、不确定性 | 数据/日期/资本/费用不一致时禁止直接比较，先建立对照运行 |
| 10 保留或淘汰 | 对候选继续观察、保留、暂停或退役；合格者形成晋级申请 | 决策规则、原因、证据、人或程序身份 | 不自动替换正式方案，不删除失败实验 |
| 11 生成日报 | 汇总执行、质量、名单原因、验证、组合、到期结果、对比、决定及下一步 | 结构化日报、可读摘要、证据链接、版本 | 上游异常仍生成异常/降级日报，后续结果追加修订版 |

### 执行顺序需要两个时钟

收盘研究生成的是未来执行计划，不能凭收盘后获得的信号按同日收盘价无条件成交。已存在的模拟订单在预登记的下一个交易时段按当时行情核算，收盘后才进行净值评价。这部分与当晚新候选的历史回测并行。

日常任务的期限、重试次数、夜间候选预算、日报截止时间可配置。非交易日不新增交易观察批次，可进行离线实验和维护。日报可链接尚在运行的实验，而不是无限等待。

## 5. 指标必须有清楚的口径

| 指标 | 定义与展示要求 |
| --- | --- |
| 超额收益 | 策略费用后区间收益减基准区间收益，以百分点展示；基准、累计/年化、收益是否复利明确标注 |
| 最大回撤 | 连续净值相对历史峰值的最大下降，附日期和修复期；起始资金也纳入峰值序列 |
| Sharpe | 日净收益减版本化无风险收益后计算；零方差、短样本或不规则估值显示不可用/样本不足 |
| 信息比率 IR | 日主动收益均值除以跟踪误差，同频率年化，与 ICIR 分开 |
| IC / RankIC | 全部合格截面预测分数与未来收益的 Pearson / Spearman 相关；5/20/60 日分别计算，不能只看入选股票 |
| 换手 | 采用明确单边定义：`0.5 ×（买入成交额 + 卖出成交额）/ 调仓前净值`；资金进出和首次建仓另列；与成员替换比例区分 |
| 容量 | 多档资本、参与率、成交额、冲击和失败成交的压力测试；仅有日线时标注粗估，不能当作保证可成交金额 |
| 市场阶段稳定性 | 用当时已知信息定义趋势/波动阶段，列每阶段样本数、超额、回撤、IR、IC；没经历的阶段显示证据不足 |
| 准确率 | 方向命中、盈利比例、事实核验各有独立分母和到期期限，仅作为辅助 |

比较先满足数据、验证、执行、风险与容量硬约束，再看收益改善；不使用一个不透明总分抵消硬性失败。短期批次评价与长样本组合指标分别展示，不能拿 5 日 Sharpe 和多年 Sharpe 排名。

## 6. 独立样本外验证怎样落实

1. 实验前登记：假设、变更范围、股票池、基准、资本、费用、窗口、主指标、风险底线、最小有意义改善、样本量与试验预算。
2. 研发只用训练/验证区间，按日期整体切分全部股票；标准化、特征选择和参数拟合只在允许的历史区间进行。
3. 依据标签实际起止时间清除跨边界样本并设置隔离；不能只写一个 `gap` 参数就视为无泄漏。
4. 最终测试集由独立验证服务持有，提交冻结配置和代码哈希后检验。优化器不能拿逐样本结果继续搜索。
5. 测试结论一旦公开并用于改进，该窗口就不再是下一次修改的独立留出集；改用新窗口或真实前瞻。
6. 全部试验及失败进入账本，防止只报告最好的一次。预登记多重检验/序贯检验政策，重叠收益标签用适当的时间块估计不确定性。

60 个交易日是可以配置的观察长度示例，不是通用的「统计验证通过」标准。历史检验、真实前瞻和不同市场阶段的充分性分开判断。

## 7. 数据与模拟必须可信

- 股票池保存当时成员，包括后续退市证券；不把今天存续股倒灌到历史。
- 财务数据记录公告及系统实际可见时间，不能用报告期末日期假装当时已知。
- 行情的复权研究序列与可成交原始价格区分；记录公司行动、费用和交易规则的生效版本。
- 执行模型处理价格限制、停牌、交易单位、可卖数量、现金、部分成交、税费、滑点与冲击；上线前核实适用规则，不在设计稿中永久硬编码费率。
- 每个策略版本有独立研究组合，历史回放和前瞻模拟共用执行内核。当前 `paper_service.place_order()` 的缓存价即时成交不能直接作为此处的次日执行模型。
- 缺报价和退市不能通过删除失败样本改善收益；估值与可交易性状态分别保存。

## 8. 实验档案必须包含什么

| 信息组 | 必需内容 |
| --- | --- |
| 身份与关系 | experiment_id、parent_experiment_id、策略版本、运行 ID、创建者、创建时间、生命周期 |
| 变更与目的 | 假设、修改前后 diff、修改理由、预期改进、失败条件、预算 |
| 输入版本 | 数据快照、历史股票池、行业、因子集合、因子代码/方向/处理规则、参数、基准、资本 |
| 执行版本 | 费用/执行/验证协议、代码提交及未提交补丁哈希、环境和依赖锁、随机种子 |
| 模型证据 | 服务商、模型标识及可得实际版本、提示词、工具集、请求/响应原文；区分重放与重新生成 |
| 完整时间线 | 每阶段开始/结束、等待/重试/失败、输入/输出产物、错误分类、证据链接 |
| 判断与结果 | 事实核验、方向预测、研究假设分别评价；预定到期、判断依据、正确/错误/未成熟/不足 |
| 对照与处置 | 与旧方案的改善和退步、保留/淘汰原因、审批、生效、回退、下一步假设 |

LLM 只负责受约束的假设建议、证据解释和日报叙述，不能自行评判自己的结论正确，也不能改写确定性评分。不可检验的文字判断需要人工复核或标记不可判定。

实验失败分为「执行失败」「假设不成立」「证据不足」。被排除后上涨的个股可进入反事实诊断，但不能凭此宣称当时一定能成交获利。

## 9. 自动进化与人工切换的权限边界

候选生成 → 冻结参数 → 回测与验证 → 影子观察 → 提交申请 → 人工批准 → 按计划生效。

自动任务可在白名单参数和注册因子中产生新版本，可按预登记政策管理候选；不能修改正式槽、不能取得人类审批令牌。初版不允许任意生成代码带生产凭据运行；后续代码实验另设离线沙箱。

晋级申请绑定：候选版本、当前正式版本、比较协议、证据包哈希和拟生效时间。审批时服务端重查权限、全部门槛、证据是否仍有效以及正式版本是否变化。输入编号和二次确认是界面辅助，真正权限和并发约束必须在服务端。

确认后安排下一个允许的交易日生效；历史结果不回写。旧正式进入可回退的冻结状态，其后续正式收益止于切换点，新方案不能接管旧收益历史。回退仍是有记录的人工决策。

现有 `/api/automatic-selection/strategies/{id}/promote` 必须接入同一治理服务；不能仅在新 UI 添加门槛而保留旧接口绕行。后台身份无 `evolution:approve` 权限，正式写入由专门审批路径承担。

## 10. 与现有代码怎么衔接

本次继续使用已核对过的现有基础，不推倒重建。核查详情见 [v1 技术附录](daily-research-evolution-plan.md)。

| 已有模块 | 复用 | 改造边界 |
| --- | --- | --- |
| `rhythm_scheduler` | 15:45 数据、16:10 选股入口，交易日/认领/恢复 | 增加可恢复阶段依赖，拆开日常队列和重计算队列 |
| `automatic_selection_*` | 策略生命周期、配置哈希、候选、排除证据、运行、前瞻评价 | 增加实验/协议关联、同口径比较、治理政策；旧简化评价明确 legacy 版本 |
| `factor_service` | 已有因子分析与 Spearman 统计 | 扩展全 A 增量计算、严格可见时间、统一 IC/RankIC 与独立验证 |
| `backtest_*` | 指标和已有行情适配 | 统一研究执行内核，不直接把最多 20 标的的现有组合回测当成全 A 动态策略引擎 |
| `paper_*` | 账户并发与虚拟记账思路 | 新增策略隔离研究账本，不覆盖个人手工模拟盘 |
| `agent_runtime` | 持久任务、工具证据、模型请求记录 | 执行解释和候选建议，不承担最终排名和审批 |
| `AutomaticSelectionView.vue` | 当前真实运行入口与现有数据 | 扩展三页研究进化导航，逐步替换展示，不另起一套相互矛盾的策略库 |

新增实体建议：`research_cycles/steps`、`research_experiments`、`research_validation_protocols`、`research_artifacts`、`research_evaluation_tasks/metrics`、`research_comparisons`、`research_claims/verdicts`、`research_paper_*`、`research_decisions/reports`。

保留三个关联：策略版本 → 多个实验；实验 → 多次每日运行；运行 → 不可变产物与评价。数据修订和重新计算追加新版本与替代关系，不覆盖旧结论。

计算任务按「交易日＋版本＋数据快照＋协议＋阶段」幂等；重试保存 attempt。计算、API 和 LLM 工作者分开，CPU/内存/并发/模型预算有上限。断点恢复不能重复模拟成交或重复审批。

读取沿用 `data:read`，提出实验、运行、审批分开授权；市场共享研究数据与用户私有持仓分离。日报默认站内可查，外部发送另行配置。

## 11. 建议分三次上线

| 交付阶段 | 可交付结果 | 验收重点 |
| --- | --- | --- |
| A 可信执行与账本 | 每日研究台接入现有运行；数据质量门、实验身份、全版本清单、失败日志、异常日报 | 数据迟到不产出假成功，重试不重复写入，任一记录可追溯 |
| B 成本与独立验证 | 统一模拟执行、全 A 因子任务、独立验证协议、完整指标、同口径对照和到期任务 | 防未来数据、成本/公司行动/未成交核算、5/20/60 日到期正确，样本不足留空 |
| C 受控进化与审批 | 白名单候选迭代、保留/淘汰、影子运行、进化台、人工晋级和回退 | 自动身份不能替换正式，旧接口不能绕行，审批冲突可恢复，失败历史保留 |

在 1 名后端、1 名量化、1 名前端，且历史数据与权限齐备的前提下，工程初估 5–8 周；先做数据审计与压测再锁定排期。真实前瞻观察按交易日自然推进，不纳入「代码写完即可完成」的承诺。

首版先跑有限因子族和参数空间，完成连续 5 个交易日端到端无人干预运行及故障恢复验收，再逐步增加候选预算。每日自动研究不意味着每天必须产生或晋级一个新策略。

## 12. 评审前需要确定的业务配置

主基准、研究资金规模、风险和容量硬约束、允许因子范围、独立验证与前瞻政策、审批负责人、日计算/模型预算。方案提供配置位置，不用随意的演示阈值替老板确定策略风险。
