# 自我进化功能实施方案

> 配套《产品设计方案 V1.6》第六章。当前 hermes-stock 五条进化路径均为 0%，本方案给出从零落地的工程路径与开源框架选型。
> 前置探查结论见同目录偏差评估：当前系统的 `ai/memory.py`(UserMemory) 是**用户画像记忆**，不是经验库；`Position.thesis` 是自由文本，无论点假设；`AgentProfile.model_primary/backup` 是主备切换，不是竞技场。

---

## 0. 一句话定位

自我进化 = **"让系统用自己的成绩单改自己"**。难点不在"能进化"，在"防过拟合地进化"——一只股票碰巧对了 5 次就疯狂加权，实则是噪音。所以本方案的核心是**证据驱动的闭环 + 多重防自欺护栏**。

---

## 1. 进化闭环与前置依赖

进化的本质闭环：

```
记账 → 对账 → 归因 → 改进 → 回测验证 → 上线(回归集把关) → 影子组对照
                                                  ↑                ↓
                                                  └── 恶化即回滚 ─┘
```

**前置依赖（不可跳过）**：预测台账 + 自动对账（超额收益口径）是进化的**燃料**。当前系统台账/对账 = 0%，所以进化的第一步不是写进化逻辑，而是**先把燃料层建起来**。没有成绩单，进化无从谈起。

两条进化类型：
- **参数级进化**：信号权重、模型竞技场（调现有参数）
- **知识级进化**：经验库、因子工厂、论点监测（往系统加新知识/新工具）

## 4. 五条路径详细方案

### 4.1 信号权重再平衡

- **现状**：0%。无因子表、无命中率统计。
- **目标**：因子/信号按超额命中率升降权，月度一次，单次调幅 ≤ 15%，≥ 50 笔闭环才启用。
- **框架**：Qlib（因子计算 + 分层收益统计）+ Optuna（权重优化，TPE + 约束）。
- **数据模型**：
  - `signal_weights`（signal_id, weight, last_updated, sample_count, oos_sharpe）
  - `signal_performance`（signal_id, period, hit_rate, excess_return, sample_size）
- **工作流**：月度批处理 → Qlib 算各信号样本外分层收益 → Optuna 在"样本量 ≥ N + 调幅 ≤ 上限"约束下优化权重 → 回归集验证 → 影子组对照 → 上线。
- **门槛**：累计 ≥ 50 笔闭环；样本不足的信号不动；附 bootstrap 置信区间。
- **留档**：每次权重变更入 MLflow，支持一键回滚。

### 4.2 经验库进化

- **现状**：0%。**注意：现有 `ai/memory.py`(UserMemory) 是用户画像记忆，不是经验库，不能混用——但底层向量检索层可复用。**
- **目标**：复盘结论 → 结构化经验条目（带样本量 + 统计强度）→ 混合召回注入 → 成绩回填 → 无效自动降权归档。
- **框架**：LlamaIndex（在现有 ChromaDB/Milvus 上包经验层）+ 保留现有 rerank。
- **数据模型**：
  - `experience_entries`（id, content, tags[], market_env[], sample_size, statistical_strength, status[observing/active/archived], injected_count, avg_post_injection_return）
  - `experience_injections`（entry_id, decision_id, injected_at, post_return 回填）
- **检索契约**：标签 + 市场环境标签 + 向量语义 三路混合（LlamaIndex `MetadataFilters` + vector + rerank），相关性门槛，单次注入上限 3 条，按历史有效性排序。
- **新条目保护**：观察模式一个月（只记录"假如注入会命中什么"，不实际注入），期满复核放行。
- **自动降权**：经验条目本身被对账——引用它的决策成绩回填，长期无效自动降权归档。
- **留档**：每次注入留痕（injection 表），季度人工抽检检索相关性入月报。

### 4.3 因子工厂（RD-Agent）

- **现状**：0%。**注意：现有 `get_stk_factor()` 只是透传 TuShare 技术因子数据，不是因子工厂。**
- **目标**：AI 提因子假设 → 自动写因子代码 → 历史回测 → 统计门槛准入实盘因子库。
- **框架**：微软 RD-Agent（方案钦点，自动假设 → 生成代码 → 执行 → 迭代）；MVP 可先用 Qlib 因子表达式 + LangGraph 编排"假设 → 写码 → 回测 → 评审"小循环，等量大了接 RD-Agent。
- **数据模型**：
  - `factor_hypotheses`（id, hypothesis, code, status, proposer_model）
  - `factor_backtests`（factor_id, period, oos_return, oos_sharpe, turnover, capacity, monotonicity）
  - `factor_library`（准入的实盘因子）
- **工作流**：季度一批 → AI 提假设 → 生成 Qlib 因子表达式 → Qlib 回测（扣费/滑点/T+1/涨跌停/退市股/三段式 + 滚动窗口）→ 样本外分层单调性 → 统计门槛 → 准入。
- **门槛**：沿用 3.2 回测协议；样本外收益显著且换手可承受才准入；产出仅作候选因子来源。
- **留档**：每个因子的假设/代码/回测全入 MLflow。

### 4.4 模型竞技场

- **现状**：0%。**注意：现有 `AgentProfile.model_primary/backup` 是主备切换，不是并行竞技。**
- **目标**：同岗位多模型并行记分，过程分（日频）为主依据、结果分为长期参考，连续两季过程分落后且差距显著才换血。
- **框架**：LiteLLM（多厂商路由 + 成本统计 + 真实模型版本号落库 + fallback）+ LangGraph（竞技编排）+ MLflow（计分留档）。
- **数据模型**：
  - `arena_matches`（岗位, model_a, model_b, period, process_score_a/b, result_score_a/b）
  - `llm_call_logs`（每次调用的 prompt/响应/真实版本/token/成本——**顺带补方案 7.2 全量留档**）
- **过程分指标（日频可得）**：数字失实率、分析师评分与后市收益相关性、假设判定准确率、裁判判定被市场验证率。
- **换血决策**：连续两季过程分落后且差距显著（bootstrap 置信区间不重叠）才换；换入当期新旗舰。
- **副产品**：LiteLLM 统一网关正好补上方案 7.2 的"按岗位路由 + 按数据许可路由 + 限流 + 计费 + 降级 + 真实版本落库 + 成本熔断"——一举两得。

### 4.5 论点存活监测

- **现状**：0%。**注意：现有 `Position.thesis` 是自由文本，无假设拆解、无 DSL、无体检。**
- **目标**：每笔买入论点拆 3~5 条可证伪假设 → DSL 校验绑定"字段 + 阈值 + 频率" → 每日体检标存活/受伤/死亡 → 死亡绊线触发推警报 → 论点级归因。
- **框架**：Pydantic（假设 DSL 结构化校验）+ LangGraph（每日体检 Agent，多假设并行检查）+ Great Expectations（可选，"字段 + 阈值"数据断言引擎）。
- **数据模型**：
  - `thesis_hypotheses`（position_id, idx, statement, field, operator, threshold, frequency, status[alive/injured/dead], last_check_at, human[bool]）
  - `thesis_pre_mortem`（position_id, 假想失败复盘, 绊线清单）
- **DSL**：受限语法，如 `单季毛利率环比>=0，季检` → Pydantic 校验 field=单季毛利率环比, op=>=, threshold=0, freq=quarterly；绑定不了库内字段的退回决策官重写；`human=true` 的假设不参与自动体检。
- **工作流**：买入即拆假设 + 事前验尸 → 每日 rhythm_scheduler 调度 LangGraph 体检 Agent 对照最新数据标注状态 → 死亡即飞书推送 → 结算时论点级归因（哪类假设最常错）。
- **防博弈**：判别力审计——统计假设死亡率/触发率，长期零死亡的模板退回重写规范（防"永不死亡"的合规假设）。

## 5. 共用基础设施

- **台账对账引擎**：Qlib 的 portfolio accounting（复用 A 股会计规则）+ pyfolio 归因。新增 `prediction_ledger` 主表（禁止 UPDATE/DELETE，PostgreSQL 权限层 + 触发器留痕）、`user_executions` 关联表（唯一可人工写入）。
- **黄金回归集**：pytest + DeepEval，三层判据（结构合法 → 方向/标签一致 → 数字溯源通过），固定温度 + 模型版本，变更自动存档支持一键回滚。
- **影子对照组**：双配置并行（迭代版 vs 冻结基准版），月度对比，迭代版恶化即回滚。
- **MLflow**：统一追踪所有权重版本、模型版本、因子版本、A/B 实验、回归集结果。

## 8. 防自欺护栏（五原则落地）

1. **干净考题**：AI 层只认前向模拟盘 + 准干净回测（模型知识截止日早于窗口 + 只用 P0 逐日存档资讯）。
2. **增量问责**：量化-only 对照基线（Qlib 跑纯因子 Top-N 无 LLM），LLM 层价值 = 完整流水线 − 量化 only。
3. **影子对照组**：不迭代基准并行，发现恶化就回滚（不证明进化有效，只防恶化）。
4. **统计门槛**：≥ 50 笔闭环、调幅上限、bootstrap 置信区间、样本量披露入月报。
5. **模拟盘先行**：新因子/新权重先模拟盘跑够周期才上正式。

---

## 9. 风险与红线

- **RD-Agent 落地门槛**：较重，需评估团队承接能力；MVP 先用 Qlib + LangGraph 轻量版，后期接入。
- **TradingAgents / RD-Agent 对 A 股规则适配差距**：T+1/涨跌停/数据接口，需 P0 技术预研（方案附录 E 已列）。
- **LiteLLM 自建网关稳定性**：需评估其 fallback/限流在生产环境的可靠性。
- **经验库污染风险**：新条目观察模式一个月、注入留痕回填、季度人工抽检。
- **论点"永不死亡"风险**：判别力审计（死亡率/触发率），零死亡模板退回重写。
- **模型竞技场过早换血**：连续两季 + 差距显著 + 置信区间不重叠才换，过程分主依据。
- **小样本过拟合**：bootstrap 置信区间 + 样本量披露常设月报。
- **红线**：量化-only 对照若长期显示 LLM 层帮倒忙 → 降级/裁撤 LLM 层；这是止损纪律，不是建议。
