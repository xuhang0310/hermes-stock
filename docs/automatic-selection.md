# 自动选股：首期功能与验收说明

## 边界

**只自动选股，不自动交易。** 本功能不会连接券商、调用模拟盘下单或创建任何订单。分数是配置规则内的横截面排序，不是收益预测。LLM 只能解释已落库的结果，不能改分、重排或晋升策略。

首期是从上线日起积累证据的前瞻研究，不是完整历史时点数据平台，也不是可执行交易回测。特征与评估已按复权因子换算价格，但仍未模拟涨跌停、停牌成交失败、整手与真实容量，不构成投资建议或交易指令。

## 每日执行链路

1. **15:45 数据入库**：内置任务 `automatic-selection-data-1545` 同步市场、L/P/D 股票目录、交易日历、复权因子（`stock_adj_factors`）和所需因子。
2. **16:10 自动排名**：内置任务 `automatic-selection-1610` 只读取本地数据；页面“立即运行”同样不抓取全市场。
3. 两项任务共用认领互斥组及数据库命名锁。排名在读取水位、目录、行情、基础指标、因子之前取得锁，提交确定性证据后释放。评估更新及 LLM 解释不占用排名输入锁。
4. 两项内置日任务支持同日错过配置时刻后的补跑，调度幂等键仍使用配置时刻。排名等待入库结束，不会与半批数据并行。已认领后执行失败的任务需通过人工触发重试，不会每分钟无限重试。
5. 数据完整性及最新入库任务状态都必须满足条件。较新的失败入库不能被较早的成功记录掩盖。因子失败单独披露，由依赖该因子的策略门禁阻断，不影响不依赖它的策略。

本地权威日历必须覆盖请求当天，且历史区间不能缺日期。若没有可信目标交易日，记录失败而不把昨天行情或请求日期冒充本日排名。日历未覆盖当天时，应先执行数据入库任务；排名接口本身不外呼补日历。

## 排名与证据

默认 Top-30，特征为估值、动量、流动性、低波动；先按 1%/99% 分位去极值，再做横截面 z-score 和绝对权重归一。并列按股票代码排序，应用行业和市值分桶约束后等权。

20 日窗口要求 **21 个预期交易日收盘价**，用于计算 20 个相邻收益率；成交额使用最后 20 个观测。停牌或缺失行情不能用更早的行情代替。

动量与波动按**后复权价**（`daily_bars.close × stock_adj_factors.adj_factor`）计算，送转、分红的除权缺口不会被当成下跌。窗口内任一日缺复权因子时，该股以 `adj_factor_missing` 排除，并计入历史窗口覆盖率；本地缓存检查也要求每个历史交易日的复权因子覆盖达到历史门槛。前瞻评估的开盘入场价与逐日收盘价同样乘同日因子，明细保留原始价与入场、退出因子以便复核。该口径自 `forward-selection-v3` 起生效，此前版本的运行不能作为 v3 的晋升证据。默认门禁：

| 项目 | 阈值 |
| --- | --- |
| 目标日行情覆盖 | 90% |
| 目标日基础指标覆盖 | 85% |
| 完整历史窗口覆盖（含复权因子） | 85% |
| 行业覆盖（启用行业约束时） | 80% |
| 策略要求的外部因子覆盖 | 100% |
| 合格股票数 | 至少 1000 |

- 每个观察日的股票目录整批冻结，重跑读取冻结快照，不读可变目录代替它。当日新发现的目录元数据在下一个观察日生效。
- 候选记录保留排除原因、约束原因、原始特征、z-score、排名、成员变化和历史输入序列。
- 输入指纹包含评分实现版本、预期交易日、历史输入及前次选中证据；更改评分语义需更新 `SCORING_IMPLEMENTATION_VERSION`。
- 相同输入重试复用当前结果；数据修复建立保留旧记录的替代链，输入恢复到历史值时也不会错误复活已被替代的运行。
- 配置只能创建新版本。运行时若配置规范化后不再匹配保存的哈希，则记录失败，不能默默补门槛后沿用旧哈希。
- 单独记录 LLM 状态；解释失败不改已完成排名，也不创建订单。

## 策略治理与前瞻评估

支持 `official / challenger / shadow / retired`。正式策略最多一个；晋升、降级、退役都有审计事件，不提供删除或自动晋升入口。

人工晋升至少需要一个同配置、同评分实现版本、质量门通过且未被替代的完成运行，并有已到期的 5 日评估。组合及合格池基准覆盖均需达到策略配置与默认门槛二者中的较高值（默认 80%）。仍需人工确认说明；不要求正收益，也不要求全部 20/60 日窗口完成。**这是最低证据门槛，不代表统计验证。**

评估采用 T 日收盘后选择、下一交易日开盘入场、第 5/20/60 个未来交易日收盘退出。缺失股票计入覆盖率，成本假设固定于策略版本。被替代的运行保留历史详情，但不再进入活跃评估队列；未到期与覆盖不足重试分配独立额度，并轮换处理，避免旧任务占满队列。

## 页面与权限

入口：量化菜单下的“自动选股”，路径 `/automatic-selection`。页面面向普通用户，分四个标签：

- **今日选股**（默认）：结论条（某日选出几只、行业构成、比上期新进/保留/移出、选出后至今表现、近 N 期 5 日胜率）+ 入选列表（一句话理由、估值/走势/活跃度/稳定性四个 0–100 分、选出后涨跌、选出前 20 日复权走势）。点开个股看“为什么入选 / 需要注意 / 关键数据 / 选出后表现”，可直接问股或加自选。数据检查没通过或计算出错时，用白话说明原因并给出“查看最近一次结果”。交易日用下拉选择，不暴露 run_id。
- **历史战绩**：5/20/60 日已到期期数、跑赢合格股票平均的期数与胜率、平均差距、最好/最差一期；每期 5 日差距柱状图；每期明细可跳回当天结果。
- **选股方法**：当天的漏斗（全市场 → 通过基础筛选 → 入选）与剔除原因，基础筛选规则、打分维度与权重、挑选约束、效果检验方法。
- **高级**（`model:manage` 或 `schedule:manage` 可见）：原运行审计台（数据检查明细、全部合格/被剔除排名、因子原始值与 z 值、5/20/60 原始评估、AI 点评原文、运行记录）与策略版本管理。新建版本用表单（入选数量、维度权重、行业/市值上限、最短上市天数、最低成交额，并显示与父版本的改动），完整 JSON 保留为“专家模式”。

权限：

- `data:read`：上述只读内容。
- `schedule:manage`：“重新计算”（数据入库 + 排名流水线）；同时遵守既有任务所有权隔离，非本人任务不可触发。
- `model:manage`：创建新版本、设为正式方案（人工晋升）、停用（退役）。
- `data:write` / `agent:use`：个股详情里的“加入自选” / “问股”。

### 白话呈现层

`quant/automatic_selection_presentation.py` 只读已落库的运行、候选和评估，派生普通用户看的内容，**不回写排名、不进入 config_hash 或数据指纹**：

- 维度分：按策略权重把特征归入估值（value_pe+value_pb）、走势、活跃度、稳定性（及附加因子），用落库 z 值算加权强度，再在当天合格池里求“超过了百分之多少”（0–100）。反向权重的维度会标注且不作为入选理由。
- 入选理由取贡献最大的两个 ≥60 分维度；风险提示为规则生成（20 日涨幅 ≥20% / 跌幅 ≥10%、当日接近涨跌停、日波动 ≥3.5%、日均成交 <1 亿元、PE ≥60、上市不满一年、维度 <25 分、同行业达上限），只做提示。
- 选出后至今：下一交易日开盘到最新收盘的复权涨跌（未扣成本），合格池等权平均作对比；5 分钟进程内缓存。5/20/60 日结果仍以前瞻评估为准。
- AI 点评改为喂给模型分位分、原始指标与规则风险（不含 z 值与哈希），要求固定格式的白话输出；生成失败时退回原始证据。

接口（均为 `{success,data,message,trace_id}` 信封，`data:read`）：

- `GET /api/automatic-selection/daily?trade_date=YYYYMMDD&strategy_id=`：默认正式策略的最新一天；无此日期返回 404。
- `GET /api/automatic-selection/track-record?strategy_id=&limit=60`：已完成运行的各期 5/20/60 日结果与汇总。注意每天一期、观察期互相重叠，汇总是“典型一期”，不能连乘成累计收益。

审计台切换运行时先清空旧详情，详情及概览回退均按 `run_id` 匹配；乱序响应、加载失败不会把 A 批次证据显示在 B 批次下。候选由服务端分页，收益颜色遵循 A 股红涨绿跌。

## 验证与上线前检查

不启动应用即可执行专项测试：

```bash
python -m unittest discover -s tests -t . -p 'test_automatic_selection*.py'
```

前端回归：

```bash
node --test frontend/tests/*.test.mjs
```

前端类型检查与构建：

```bash
npm --prefix frontend run build
```

数据库集成测试仅接受 `STOCK_AUTOMATIC_SELECTION_TEST_DATABASE_URL` 指向 `mysql+pymysql` 的独立 `_test` 或 `-test` 数据库，明确拒绝 `hermes-stock`。**测试会清空并重建指定测试库的表，必须使用专用空测试库，不能填生产地址。** 未配置时明确跳过，不得将跳过计为验收通过。既有因子测试使用自己的内存测试库，不替代自动选股的 MySQL 集成验收。

发布前还需要完成：

- 隔离 MySQL 上的建表、唯一约束、事务、冻结快照、评估队列和调度集成验证。
- 获得部署授权后，核验真实 TuShare 权限、数据覆盖、任务所有者及生产调度。
- 上线后逐步积累真实的 5/20/60 交易日结果；不能提前宣称有成熟前瞻绩效。

本轮开发不包含生产建表、部署或生产写入，也不包含 `docs/upgrade-todo-2026-09.md` 中的平台升级待办。
