# 记忆系统实施方案（借鉴 claw-code）

> 本方案基于对 `E:\workspace\claw-code`（Rust 版 Claude Code 克隆 "clawd"）记忆机制的源码研究，将其**会话级记忆技术**适配为 hermes-stock 的**三层记忆架构**。与 [自我进化实施方案.md](自我进化实施方案.md) 的"经验库"部分互为深化：后者讲进化闭环，本方案讲记忆的存储/压缩/管理工程实现。

## 一、claw-code 记忆机制研究结论

clawd 的记忆是**会话级对话记忆**（Claude Code `/compact` 的 Rust 实现）。三个模块分工清晰：

| 模块 | 文件 | 职责 |
|---|---|---|
| 存储 | `session.rs` / `session_control.rs` | 数据结构 + 持久化 + 会话管理 |
| 压缩 | `compact.rs` / `summary_compression.rs` | 触发判断 + 旧消息→结构化summary + summary二次裁剪 |
| 管理 | `session_control.rs` + compact 触发控制 | 生命周期、fork血缘、轮转清理 |

### 1. 存储（session.rs）

**数据结构**：
```
Session { version, session_id, created/updated_at_ms, messages[], compaction?, fork?, persistence? }
ConversationMessage { role, blocks[], usage? }
ContentBlock = Text { text } | ToolUse { id, name, input } | ToolResult { tool_use_id, tool_name, output, is_error }
```

**持久化**：JSONL（每行一条 record，`type` 字段区分 `session_meta` / `message` / `compaction`），兼容旧 JSON 对象格式。

**四个关键工程点**：
- **追加写**（`append_persisted_message`）：push_message 只 append 一行，不全量重写 → 高性能 + 天然不可篡改
- **原子写**（`write_atomic`）：写临时文件再 `rename` → 防中途崩溃损坏
- **日志轮转**：`ROTATE_AFTER_BYTES=256KB`，超过轮转成 `.rot-{ts}.jsonl`，最多留 `MAX_ROTATED_FILES=3` 个，旧的自动清理
- **存储位置**：`.claw/sessions/{session_id}.jsonl`

### 2. 压缩（compact.rs）

**触发**（`should_compact`）：可压缩消息数 > `preserve_recent`（默认 4）**且** token 估算 ≥ `max_estimated_tokens`（默认 10000）。

**压缩结构**（`compact_session`）：
- 首条若是已压缩的 system 前缀 → 跳过
- 保留尾部 `preserve_recent` 条消息 verbatim
- 中间旧消息 → `summarize_messages` 压成结构化 `<summary>` 块
- 压缩后首条变 system continuation message（preamble + summary + "Recent messages preserved verbatim" + "Continue without asking"）

**结构化 summary 模板**（核心借鉴点）：
```
<summary>
Conversation summary:
- Scope: N earlier messages compacted (user=X, assistant=Y, tool=Z).
- Tools mentioned: bash, read, edit.
- Recent user requests:
  - <最近3条用户请求，每条截断160字>
- Pending work:
  - <含 todo/next/pending/follow up/remaining 关键词的消息>
- Key files referenced: src/compact.rs, src/session.rs.
- Current work: <最后一条非空文本>
- Key timeline:
  - user: <block摘要>
  - assistant: <block摘要>
  - tool: <block摘要>
</summary>
```

**增量压缩不丢历史**（`merge_compact_summaries`，关键借鉴点）：二次压缩时，旧 summary 的 highlights 抽出放 `Previously compacted context`，新 highlights 放 `Newly compacted context`，新 timeline 放 `Key timeline`。**多次压缩，旧教训一直带在前面。**

**token 估算**：`char_len / 4 + 1`（粗略但够用）。

### 3. summary 二次裁剪（summary_compression.rs）

对 summary 文本本身做预算压缩，防 summary 自己爆：
- 预算：`max_chars=1200, max_lines=24, max_line_chars=160`
- 步骤：normalize（折叠空白 + 去重行）→ `select_line_indexes`（按优先级 0~3 选行）
- 优先级：`core details(0)` > `section headers(1)` > `bullets(2)` > `other(3)`
- 超预算的行加 `… N additional line(s) omitted.`

### 4. 管理（session_control.rs）

- `.claw/sessions/` 目录，`latest`/`last`/`recent` 别名解析
- `list_managed_sessions`：按修改时间倒序列出，含 message_count/parent/branch
- **fork 血缘**：`fork_managed_session` 派生新 session，记录 `parent_session_id` + `branch_name`
- compaction 元数据（count/removed/summary）持久化到 JSONL 的 `compaction` record

### 关键洞察

> **clawd 只有会话级记忆，没有跨会话长期记忆。** 每个 session 独立，压缩只在 session 内累积。但它的一批工程技术（追加写、原子写、轮转、结构化 summary、增量合并、预算裁剪、fork 血缘）对 hermes-stock 的"经验库 + 台账 + 调用留档"三层记忆全部直接可用。

## 二、与 hermes-stock 需求的映射：三层记忆

hermes-stock 需要的记忆不是单一层，而是**三层不同生命周期**：

| 层 | 生命周期 | 用途 | clawd 能直接给什么 | 缺口 |
|---|---|---|---|---|
| **L1 会话记忆** | 单次对话 | Agent 对话的 context 管理（防超长） | compact.rs 几乎可直接移植 | 仅研究态，需 Python 重写 |
| **L2 经验记忆** | 跨会话长期 | 复盘结论→经验条目→检索注入→成绩回填 | 结构化 summary 模板 + 增量合并 + 预算裁剪 | **clawd 完全没有，需新建** |
| **L3 事实记忆** | 永久不可篡改 | 预测台账 + LLM 调用留档 | JSONL 追加写 + 原子写 + 轮转 | 需加哈希链防篡改 |

当前 hermes-stock 现状：
- L1：**0%**（`stock_agent.py` 的对话无压缩，超长就超长）
- L2：**0%**（`ai/memory.py` 的 UserMemory 是用户画像，不是经验库——不能混用，但向量检索层可复用）
- L3：**0%**（无台账表，`position_trades` 可物理删除/回滚，不可篡改完全没做）

## 三、详实方案：三层记忆系统

### L1 会话记忆（移植 clawd compact）

**目标**：Agent 对话超阈值时自动压缩，旧消息→结构化 summary，保留 recent 尾部 verbatim。

**实现**：把 `compact.rs` 逻辑用 Python 重写（hermes-stock 是 Python 后端），落到 `backend/app/ai/` 下新模块 `session_compact.py`。

**关键参数**（沿用 clawd 默认，可调）：
- `preserve_recent = 4`（保留最近 4 条不压缩）
- `max_estimated_tokens = 10000`（超此触发）
- summary 预算：`max_chars=1200, max_lines=24, max_line_chars=160`

**适配点**：
- clawd 的 summary 模板（Scope/Tools/Pending/KeyFiles/CurrentWork/Timeline）照搬，但 `Key files referenced` 的提取规则改成识别 A 股代码（6 位 SH/SZ/BJ）和 hermes-stock 模块路径
- summary 写入 `ai_chat_sessions`/`ai_chat_messages` 时标记 `is_compacted=True`，对应 clawd 的 `compaction` record
- 增量合并（Previously/Newly 模式）必须保留——防止多次压缩丢早期上下文

**产出**：`backend/app/ai/session_compact.py` + `ai_chat_messages` 加 `compaction_count` 字段。

### L2 经验记忆（跨会话经验库，新建）

这是 clawd **没有**的层，但借用它的三项技术：**结构化 summary 模板**（经验条目格式）、**增量合并**（旧教训不丢）、**预算裁剪**（注入预算控制）。

**与 UserMemory 严格区分**：
| | UserMemory（现有，保留） | 经验库（新建） |
|---|---|---|
| 内容 | 用户个人事实/偏好 | 复盘结论的结构化经验 |
| 字段 | memory_type/content/importance | + sample_size/statistical_strength/tags[]/market_env[] |
| 注入 | 无限制 | 单次≤3条、相关性门槛、留痕回填 |
| 失效 | 手动 archived | 自动降权归档 |
| 用途 | 个性化对话 | 分析师工作参考 |

**数据模型**（新增 3 表，复用现有向量库）：
```
experience_entries (
  id, content TEXT,                    -- 经验正文（结构化模板，见下）
  tags JSON,                           -- 行业/形态/信号类型
  market_env JSON,                     -- 风格/牛熊标签（防跨环境错配注入）
  sample_size INT, statistical_strength FLOAT,  -- 样本量与统计强度
  status ENUM(observing/active/archived),
  source_review_id BIGINT,             -- 来自哪次复盘
  injected_count INT DEFAULT 0,
  avg_post_injection_return FLOAT,     -- 成绩回填
  created_at, activated_at
)
experience_injections (                -- 注入留痕（借鉴 clawd compaction record 的留痕思想）
  id, entry_id, decision_id, injected_at, relevance_score,
  post_return FLOAT NULL,              -- 注入后该决策的成绩，回填
  human_verified BOOL DEFAULT FALSE
)
experience_revisions (                 -- 经验条目本身的版本演变（借鉴 clawd fork 血缘）
  id, entry_id, parent_revision_id, diff, reason, created_at
)
```

**经验条目正文模板**（借鉴 clawd 的 `<summary>` 结构化格式，A 股化）：
```
<experience>
场景: <行业/形态/信号类型>
市场环境: <牛熊/风格>
观察: <从 N 笔复盘中归纳的事实，附样本量 N=X>
统计强度: <置信区间/命中率>
可证伪条件: <库内字段+阈值+频率>   ← 与论点存活监测的 DSL 复用
适用范围: <何时该注入、何时禁用>
反例: <此前M次有K次失效的场景>
</experience>
```

**检索契约**（三路混合，借鉴 clawd summary 的"保核心+预算"思想）：
- 标签过滤（LlamaIndex `MetadataFilters`，对应 clawd 的优先级选行）+ 向量语义（现有 ChromaDB/Milvus）+ rerank
- 相关性门槛 + **单次注入上限 3 条**（对应 clawd 的 `max_lines` 预算）
- 按历史有效性（`avg_post_injection_return`）排序（对应 clawd 的优先级 0~3）
- 注入时在台账留痕（对应 clawd 的 compaction record 留痕）

**新条目保护**（观察模式一个月，只记录"假如注入会命中什么"不实际注入 → 期满复核放行）。

**自动降权**：经验条目本身被对账——引用它的决策成绩回填 `experience_injections.post_return`，长期无效自动 `status=archived`（对应 clawd 的轮转清理旧文件）。

### L3 事实记忆（不可篡改台账 + 调用留档）

**核心创新**：台账"不可篡改"**不靠数据库权限层+触发器，靠 append-only JSONL + 哈希链**——直接用 clawd 的追加写+原子写+轮转，再加一条哈希链防篡改。

**为什么这样比 PostgreSQL 权限层好**：
- clawd 已证明 append-only JSONL + 原子写 + 轮转在生产可用
- 追加写天然不可 UPDATE/DELETE（没有修改操作）
- 哈希链（每条 record 带 `prev_hash`）让任何篡改可被检测（像轻量区块链）
- 自带轮转和崩溃安全，不依赖 DBA 配权限

**数据模型**（双写：MySQL 索引查询 + JSONL 不可篡改原件）：
- MySQL 表 `prediction_ledger_index`（可查询索引：指令日期/股票/类型/状态），**只读自 JSONL**
- JSONL 文件 `data/ledger/{YYYY-MM}/{ledger-NNNNNN.jsonl}`（不可篡改原件，追加写）

**JSONL record 格式**（借鉴 clawd 的 type 区分 + 加哈希链）：
```jsonl
{"type":"instruction","seq":1,"prev_hash":"0000...","hash":"a1b2...","ts":...,"data":{"action":"buy","symbol":"600519",...}}
{"type":"execution","seq":2,"prev_hash":"a1b2...","hash":"c3d4...","ts":...,"data":{"user_filled":true,...}}
{"type":"settlement","seq":3,"prev_hash":"c3d4...","hash":"e5f6...","ts":...,"data":{"excess_return":0.03,...}}
{"type":"compaction","seq":4,"prev_hash":"e5f6...","hash":"...","ts":...,"data":{...}}   ← 借鉴 clawd 的 compaction record
```

**LLM 调用留档**同样用 append-only JSONL：`data/llm_calls/{YYYY-MM}/{calls-NNNNNN.jsonl}`，每条含 prompt/响应/真实模型版本/token/成本——顺带满足方案 7.2 全量留档。

**轮转**：沿用 clawd 的 256KB 阈值 + 最多留 3 个轮转文件（台账可放宽到 64MB + 保留全部，因为台账不能丢）。

## 四、从 claw-code 借鉴的技术点逐条清单

| # | clawd 技术 | clawd 位置 | 借鉴到 hermes-stock 哪里 | 怎么用 |
|---|---|---|---|---|
| 1 | 追加写（不全量重写） | `session.rs:411 append_persisted_message` | L3 台账 + 调用留档 | append-only JSONL，天然不可篡改 |
| 2 | 原子写（临时文件+rename） | `session.rs:852 write_atomic` | L3 所有持久化 | 防崩溃损坏 |
| 3 | 日志轮转 + 清理 | `session.rs:874 rotate_session_file_if_needed` | L3 轮转 | 台账保留全部，调用日志限 3 份 |
| 4 | 结构化 summary 模板 | `compact.rs:177 summarize_messages` | L1 对话压缩 + L2 经验条目格式 | A 股化（识别股票代码） |
| 5 | 增量合并不丢历史 | `compact.rs:238 merge_compact_summaries` | L2 经验库累积 + L1 多次压缩 | Previously/Newly 模式 |
| 6 | 预算裁剪 + 优先级选行 | `summary_compression.rs:128 select_line_indexes` | L2 注入预算（单次≤3条） | core>header>bullet>other |
| 7 | 触发阈值（token估算） | `compact.rs:41 should_compact` | L1 压缩触发 + L2 沉淀触发 | char_len/4+1 估算 |
| 8 | fork 血缘（parent+branch） | `session.rs:215 fork` | 影子对照组版本管理 + 经验条目版本演变 | 每个迭代版本记 parent |
| 9 | compaction 元数据留档 | `session.rs:204 record_compaction` | L2 经验注入留痕 | injections 表 |
| 10 | type 区分的 JSONL record | `session.rs:396 render_jsonl_snapshot` | L3 台账多 record 类型 | instruction/execution/settlement |

**我在 clawd 基础上的 2 处增强**：
- **哈希链**（`prev_hash`+`hash`）：clawd 只追加不校验，我加哈希链让篡改可检测——台账是钱相关，比对话严
- **市场环境标签过滤**：clawd 的 summary 无环境维度，经验库必须带 `market_env` 防跨环境错配注入（方案 6.4 明确要求）

## 五、落地步骤

| 步 | 做什么 | 框架/复用 | 产出 |
|---|---|---|---|
| 1 | L3 台账+调用留档 append-only JSONL+哈希链 | 移植 clawd session.rs 的追加/原子/轮转 | `backend/app/ai/ledger_store.py` |
| 2 | L1 会话压缩（Python 重写 compact.rs） | 移植 clawd compact.rs | `backend/app/ai/session_compact.py` |
| 3 | L2 经验库数据模型 + 检索 | LlamaIndex + 现有 ChromaDB/Milvus | `experience_entries` 等 3 表 + `experience_store.py` |
| 4 | L2 注入留痕 + 成绩回填 | 借鉴 clawd compaction record | `experience_injections` 表 |
| 5 | L2 观察模式 + 自动降权 | 借鉴 clawd 轮转清理 | 调度任务 |
| 6 | L2 经验条目版本演变 | 借鉴 clawd fork 血缘 | `experience_revisions` 表 |
| 7 | 影子对照组版本管理 | 借鉴 clawd fork | 配置 + 血缘表 |

**顺序逻辑**：先 L3（事实记忆是燃料，且 clawd 技术最直接可用）→ 再 L1（会话压缩，clawd 几乎可直接移植）→ 再 L2（经验库，最复杂，需在 L1/L3 基础上建）。
