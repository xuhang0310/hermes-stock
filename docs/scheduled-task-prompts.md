# 定时任务提示词

## 2026-11-02 版（当前）

对应生产库里 8 个启用中的 Agent 任务。上一版是 11-02 晚上整体改的，每条 900–1200 字，有三个问题：

- **每条末尾都贴着同一段约 450 字的通用规矩**：“价格须有证据”“不猜成交”“不下券商订单”“报告写完由系统自动推送一次”等。系统运行时已经会附加执行约束（`rhythm_scheduler._scheduled_execution_constraints`）和说人话要求，重复写只会让数字人把规矩复述进报告。
- **写了工具名和表名清单**：`ws_write_file`、`get_schema/run_sql`。数字人自己知道用什么工具，只需要告诉它文件放哪。
- **一句话需求被扩写成规章**：比如“查询失败的字段明确留缺失，不能用当前值伪造历史盘前值”，这一版改成“缺哪份就说缺哪份，不要补写早上的计划”。

这一版按本文后面「三、这一版怎么写」的原则重写：只写交付什么、写成什么样，每条都落到价格和股数。保留了每天的存档链路，但每个环节只存一个文件：

```text
早盘 premarket.md → 盘中 intraday-{time}.md → 午盘 midday.md → 选股 selection.md → 晚间 daily-review.md → 次日早盘
```

原来的 premarket-state.json 并进 premarket.md（清单里带上当时的持仓、可卖数量和现金），comparison.json 并进 daily-review.md。

### 早盘挂单清单（交易日 08:40）

`agent-1-a80afb924e40`

```text
今天是{date}（{weekday}），开盘前给我一份今天的挂单清单。我会照着在券商里下单，所以要具体、直白，一眼能看懂。

我要知道两件事：
1. 持仓怎么操作。三个账户分开写，同一只股票在不同账户分别写股数。每只是拿着不动、卖出还是加仓；要卖或要加的，写清楚什么价、多少股。
2. 自选里哪只可以买。写清楚哪个账户、什么价、买多少股。没有值得买的，就说今天不买。

几点说明：
- 持仓、可卖数量和现金以系统里登记的为准。现金不够时，可以用同一账户当天卖出的钱买，写清楚卖掉哪只的钱买哪只。
- 还没开盘，价格可以带条件，比如“涨到 24.13 元卖 500 股”“跌破 9.38 元卖 1,700 股”，但每条都要有价格和股数。止损这种跌破才触发的单子，和普通挂单分开列。
- 股数按交易规则取整：一般是整百股，科创板至少 200 股。
- 隔夜新闻、公告和大盘，只挑会改变今天操作的说，一两句就够。
- 上一个交易日的日报（notes/reviews/ 下那天目录里的 daily-review.md）给了明天的打算和改进建议，接着用；改了就说为什么。

写成这样：
- 开头两三句：今天总的打算，最该盯哪几只。
- 每个账户一张表：股票（最新价）｜怎么做｜价格｜股数。
- 能买的单独一张表：账户｜股票｜价格｜股数，表下面一句话说钱从哪来。

写完把这份清单，连同当时各账户的持仓、可卖数量和现金，存到 notes/reviews/{date}/premarket.md，午盘和晚上复盘要用。同一天重跑就另存一份，不要覆盖早上那份。
```

```text
早盘清单在 notes/reviews/{date}/premarket.md，前几轮提醒也在这个目录。价格碰到不等于成交，不要写成已经成交。不写公司介绍和大盘综述。
```

### 全自动选股（交易日 20:30）

`selection-action-plan-2000`

```text
今天是{date}（{weekday}），给我解读今天系统规则选出的股票，告诉我下一个交易日怎么做。

先确认今天的选股算完了没有：看 automatic_selection_runs 里今天这一次的状态，入选的是 automatic_selection_candidates 里 selected=1 的。没算完、失败或者今天没有数据，就直接说今天没有新名单，可以提一句上一次名单是哪天的；不要拿旧名单当今天的推荐，也不要自己补选或改排名。

入选不等于要买。和现有持仓重复、或者会让同一个行业太集中的，要说出来。各账户的钱按系统登记的现金算，几只一起买时别把同一笔钱算两次。
```

## 2026-10-27 版：开盘前操作策略的两个任务

> 对应生产库的两个任务：
> - `agent-1-3b70b9430012`：早盘开盘前，每日 09:00
> - `agent-1-9080ccba4484`：午后开盘前，每日 12:30
>
> 依据：2026-10-27 只读查询生产库，包括任务配置、建任务的会话、客户近几天的原话、账户资金和运行记录。

### 一、客户的原话

> 股票那个帮我把那个早盘和午盘前加两个定时任务，就是开盘前30分钟吧让他给出策略，持仓的股票应该怎么操作？具体股票每一个账户多少钱卖多少，然后在自选里面选哪个股票可以买入的具体多少钱买多少。

客户要的只有三样东西：

1. 开盘前 30 分钟送到。
2. 持仓怎么操作：分账户、分股票，什么价卖、卖多少。
3. 自选里买哪只：什么价买、买多少。

这几天客户还说过「直接给我大白话的结论 我照着操作」「让我一眼能看懂到底要干嘛 怎么干」。

### 二、前两版为什么不对

**原提示词**（总调度写的，1 673 / 1 856 字）：

- 把一句话需求扩写成规章。数字人把规矩原样复述进报告，例如"未成交卖出款不算现金""约 25% 不构成新授权"。
- 写了"完成后推送飞书"。数字人以为要自己推送，推不了就在正文里写"推送未完成"，其实系统已经推送成功了。

**第一次重写**（10-27 已上线，1 148 / 1 247 字）也不对，问题出在加了客户没要的东西：

- **把"持仓怎么操作"缩成了"卖不卖"。** 10 月 25 日"每只最多减四分之一、分两笔"是针对周一那一次操作的约定，被写成了每天的规矩，等于替客户定死了只减不加。
- **"买多少"永远是 0。** 第一次重写保留了原提示词里编出来的三条："没卖出去的钱不算""不知道现金就不给股数""不超过总资产 5%"，客户都没说过。三个账户登记的可用现金都是 0，这几条合起来，买入只能是 0 股。10-27 午间那份报告就是"三账户买入均为 0 股"。
- **夹带了会过期的细节**，比如上海谊众 37.50 元止损、平安银行样例记录。样例记录已经删除。

### 三、这一版怎么写

- 只写客户要的两件事：持仓怎么操作、自选买哪只。每一条都落到"价格 + 股数"。
- 持仓的操作可以是拿着不动、卖或加仓，不预设只减仓。
- 现金不够就用同账户卖出的钱买。A 股卖出成交后，钱当天就能用来买，所以"卖掉 A 的钱买 B"当天就能做完。
- 开盘前还不知道开盘价，允许带条件，但每一条都要有具体价格和股数。
- 不写推送、不写工具名、不写核对规章。系统层附加的执行约束和推送前的说人话改稿照常生效。
