- **成交概率偏乐观：** 统计时最高价碰到挂单价就算成交，实盘可能排不到。
- **卖单大多不会成交：** 下降和震荡趋势下，每天成交概率通常只有 2% 到 3%，持仓的变动会明显变少。

**v2 的规则和上线标准（2026-11-05 15:45，看结果前写定）：**

- **目标股数：** 打到止损（2 倍 ATR）的亏损不超过账户总资产的 X%，单只不超过总资产的 25%。X 在 2012-07 至 2018-12 上从 0.5%、1%、1.5%、2% 里选夏普最高的。

- **买回：** 持股低于目标 5% 以上，且账户有之前卖出的钱才挂，价格是昨收 -1%（v1 验证过跑赢代码选的买价），金额不超过卖出款。总仓位不会高过开始时。

**模拟：** 随机 8 只股票、满仓起步、按上面规则逐日挂单，碰到价才成交，含费用；对照是同样 8 只一直拿着。各跑 200 次，取中位数。

## 1. 目标

每张挂单的三件事都由量化模型算出来，并能说清依据：

- **挂不挂：** 算下来不划算就不挂，这也是一个结论。
- **挂多少钱：** 综合成交概率和成交之后的预期走势，算出最优价格。
- **挂多少股：** 由目标仓位和风险预算决定，可以分几档挂。

数字人只负责解释结果，不能改价格和股数。系统不接券商，单子仍由客户自己下。

## 2. 和现在的差别

| | 现在 | 方案 |
|---|---|---|
| 卖价、买价 | 模型读完数据后给一个数 | 对每个候选价格算成交概率和预期，取最优 |
| 股数 | 模型判断 | 当前持仓和目标仓位的差额 |
| 依据 | 一段文字，每次说法不同 | 固定的特征和模型，同样的数据得到同样的结果 |
| 对不对 | 事后凭感觉 | 每张单预测的成交概率和实际对照，自动统计 |
| 模型（LLM）的作用 | 做决定 | 解释结果、解读公告 |

## 3. 已有的研究结论

详见 `technical-signal-plan.md`。这些结论决定了不能走简单规则这条路。

- **单一指标择时预测不了涨跌。** MACD、均线、唐奇安、ATR 吊灯等五套规则，全市场验证都不如一直拿着；MACD 转绿、转红后 10 日的超额都接近 0。
- **“反弹就卖”接近抛硬币。** 卖后 10 日上涨的占 49%。
- **挂单价离昨收越近，越没有信息。** 2012 至 2019 年的数据里，昨收 +1% 的卖单卖后还跑赢市场，挂得越高卖后越跑输。这一条还没有在 2019 年以后的数据上确认，只能当线索。
- **成交本身带信息。** 买单在下跌时才成交，所以这段数据里单纯挂低价买入没有优势。这是最优挂单要解决的核心问题：只看价格好不好不够，要算“在这个价成交”之后会怎样。
- **横向比较比预测单只涨跌有效。** “20 日成交额小”通过了验证，过去 60 日涨得多的反而跑输。它们是好特征，但不是完整的系统。

## 4. 引擎结构

### 4.1 数据

全市场 2012 年以来的日线（含已退市股票）、复权、每日指标（换手率、市值）、资金流向、筹码、涨跌停价、指数。TuShare 这些接口代码里已经在用。历史数据作为研究数据存放，线上只留计算需要的长度。

### 4.2 特征

每天收盘对全市场算一遍，先做横截面标准化：

| 类别 | 内容 |
|---|---|
| 趋势 | 均线排列和斜率、MACD、ADX |
| 动量和反转 | 1、5、20、60 日收益 |
| 波动 | ATR、已实现波动率、振幅、跳空 |
| 量能 | 量比、换手率、成交额排名、量价背离 |
| 位置 | 布林带位置、RSI、KDJ、距 20/60/120 日高低点的距离 |
| 筹码和资金 | 获利盘比例、成本集中度、大单净流入 |
| 市场状态 | 指数趋势、上涨家数、涨跌停家数、市场波动 |

`quant/factors/zoo` 已有的 alpha101、gtja191、qlib158 也进候选。每个特征先过 IC 检验，没有预测力的不进模型。`tech_signal.py` 里的指标计算直接复用。

### 4.3 预测

三个模型，都按时间滚动训练，只用当时能看到的数据。先做简单基线，模型跑不赢基线就不用。

1. **未来收益排名：** 这只股票未来 5、10、20 日相对全市场的分位，决定谁该多拿、谁该少拿。
2. **明日价格分布：** 明天开盘、最高、最低、收盘相对昨收的分位数，由此得到“挂在 p 成交的概率”。
3. **成交之后的走势：** 已知价格碰到 p，之后 N 日的预期收益。这一项专门处理第 3 节说的成交带信息问题。

### 4.4 挂单优化

对每只要操作的股票，在当天涨跌停范围内按价格网格逐个计算：

```
卖单价值(p) = 成交概率(p) × [ (p − 成交后预期价格(p)) / 昨收 − 费用 ]
买单价值(p) = 成交概率(p) × [ (成交后预期价格(p) − p) / 昨收 − 费用 ]
```

- 取价值最大的价格；最大值不大于 0 就不挂。
- 股数较大时分 2 到 3 档挂，每档各有成交概率。
- 止损单单独算：它的作用是控制风险，距离由波动率和单只风险预算决定，再用回测确认它的代价。

### 4.5 组合和风控

- **目标仓位：** 由收益排名和波动率算出，有单只上限、行业上限；总仓位随市场状态调整。这一层负责第 3 节那个选股规则解决不了的回撤问题。
- **股数：** 目标仓位减当前持仓，差额才是要买卖的量。三个账户分开算。
- **交易约束：** T+1、整手、科创板 200 股起、可卖数量、涨跌停、现金来源，沿用 `plans/rules.py` 和 `plans/service.py` 的校验。

### 4.6 解释和呈现

- **早盘：** 09:15 前出计划。午盘挂单调整重新算一次，要用盘中数据，先确认 `rt_min`/`stk_mins` 的权限。
- **校验：** `save_trade_plan` 拒绝和引擎结果不一致的价格和股数。
- **H5：** 每张单显示价格、股数、成交概率、预期、主要依据。
- **到价提醒：** 现有 `plans/watcher.py` 继续用；加一种“走出预期区间”的提醒，由模型区间触发。

### 4.9 买入模型（标准写于 2026-11-05 21:03，看结果前）

**要解决的问题：** 买单只在下跌时成交，所以只看价格低不够，要判断“在这个价买到之后会怎样”。卖价那张统计表用在买价上没跑赢昨收 -1%。

**模型：** 候选价是昨收减 k 倍 ATR（k 取 `BUY_GRID`），对每只股票每个候选价估两个数：成交概率 P（梯度提升二分类）、成交后 10 日相对全市场的走势 E（梯度提升回归，只用碰到过的样本训练）。价值 = P × (E - 买入费用)，取最大的价，都不大于 0 就不挂。特征只用线上每天算得出的，不用涨跌停价。

**第一关（2015 至 2018，每年只用之前的数据训练）：** 每个股票日的价值（没挂单算 0）均值高于昨收 -1%，且至少 3/4 年更好，不过就停。这段里比较 4 种做法，选均值最高的一种进第二关：

1. 模型 1 的 7 个特征，两个模型相乘。
2. 7 个特征加 7 个短期和波动特征（`atr_pct`、`rv_20`、`ret_1`、`ret_5`、`range_1`、`close_pos`、`vol_ratio_5`），两个模型相乘。
3. 同 2，再要求 E 扣费后至少 0.2%（和卖单的门槛一样）。
4. 同样 14 个特征，只训练一个模型，直接预测“成交才算”的价值。

**第二关（2019 年之后只跑一次，每年只用之前的数据训练）：** 三条都要满足。

1. 每个股票日的价值均值大于 0，高于昨收 -1%，至少 60% 的年份更好。
2. 换进影子 B 的规则（只换买回价，买不买也听模型），随机 8 只跑 200 次取中位数：夏普至少高 0.03，最大回撤最多深 5 个百分点，至少 60% 的年份夏普不低于用昨收 -1% 的版本。
3. 压力测试：穿过挂单价 0.3% 才算成交、费用翻倍，年化不低于同样压力下用昨收 -1% 的版本。

**和卖出模型标准的差别：** 卖出模型卡在“成交概率偏差不超过 3 个百分点”。买入模型把这条从门槛改成只报告，因为这里的概率只用来比较同一只股票的几个候选价，不展示给客户，也不决定仓位；能不能用由实际价值和模拟决定。这条放宽是看买入结果之前定的。

**通过之后：** 用全部数据训练并导出，真实账户的买价校验用它，另开影子 C。影子 A、B 比较期间不改。没通过就继续用昨收 -1%，并如实记录。

**第一关结果（2026-11-05 21:23）：通过，选第 3 种进第二关。** 每个股票日的价值（2015 至 2018 平均）：

| 做法 | 价值 | 基线昨收 -1% | 同一批股票挂昨收 -1% | 高于基线的年份 |
|---|---:|---:|---:|---:|
| 1. 7 个特征 | +0.012% | -0.304% | -0.054% | 4/4 |
| 2. 14 个特征 | +0.037% | -0.304% | -0.019% | 4/4 |
| **3. 14 个特征，扣费后至少 0.2%** | **+0.041%** | -0.304% | +0.006% | 4/4 |
| 4. 一个模型直接预测价值 | +0.029% | -0.304% | -0.062% | 4/4 |

价值大部分来自“不挂”，也就是避开买了也会跑输的股票（-0.304% 到 +0.006%），选价本身多贡献约 0.035 个百分点。第 3 种的挂单率约 58%，成交概率最大偏差 3.9 到 5.4 点（只报告）。

换进影子 B 的规则（2015 至 2018）：年化 +7.74%，用昨收 -1% 是 +7.04%；最大回撤 -45.31% 对 -46.51%；夏普 0.414 对 0.382；3/4 年夏普不低于 -1% 版本。

**第二关结果（2026-11-05 21:46，只跑了一次）：三条都通过，但优势不大。**

| 2019 年之后 | 买入模型 | 昨收 -1% |
|---|---:|---:|
| 每个股票日的价值 | +0.126% | +0.043% |
| 价值更高的年份 | 7/8 | |
| 影子 B 规则的年化 | +15.05% | +14.79% |
| 最大回撤 | -31.93% | -32.84% |
| 夏普 | 0.753 | 0.712 |
| 夏普不低于 -1% 版本的年份 | 6/8 | |
| 压力测试年化 | +13.18% | +13.17% |

要如实看的三点：

- **价值来自“买不买”，不是“买多少钱”。** 同一批股票也挂昨收 -1%，价值是 +0.1263%，和模型选的价 +0.1264% 一样；分年看模型只有 5/8 年更高。模型能避开买了也会跑输的股票，但选价相对 -1% 没有证明有额外价值。
- **模拟里的优势很小。** 夏普只比门槛多 0.011，年化多 0.26 个百分点，8 年里有 5 年年化比 -1% 版本低，压力测试基本打平。部分改善来自买得更少（年换手 3.73 倍对 4.23 倍）。
- **同一段数据今天已经用来验证过几条别的规则，** 每条各跑一次，但这段数据不再是完全没看过的。

上线的就是通过验证的这个规则（听模型买不买，买的话用模型的价），不换成“听模型买不买、价格用 -1%”：那个组合没有单独验证过。

## 5. 上线门槛

指标和数值在写模型之前定稿，之后不改，下面是初稿。训练和测试严格按时间分开，2019 年以后只用来验证。

| 门槛 | 要求 |
|---|---|
| 成交概率准不准 | 样本外按预测概率分组，实际成交率和预测相差不超过 3 个百分点 |
| 排名有没有用 | 10 日 Rank IC 均值不低于 0.03，至少 60% 的年份为正 |
| 挂单有没有价值 | 扣费后每张单的价值高于两个基线（昨收 +1%、固定倍数 ATR），至少 60% 的年份如此 |
| 组合 | 夏普不低于一直拿着加 0.10，最大回撤明显更小，费用翻倍后依然成立 |
| 影子运行 | 实盘数据上跑 4 周，只记录不推送，成交概率仍然校准，且结果不差于同期 AI 计划 |

任何一条没过都不上线，如实报告。

## 6. 阶段 3 消息驱动

**现状（2026-11-05）：代码已写好，还没部署。** 实现在 `backend/app/events/`，表 `market_events`，任务 `message-watch-15m`。目前做到“计划页和触价提醒标消息待复核”和“排队消息并入下一份报告”；“严重事件暂停挂单”和“事件进特征库”要等引擎（Q2、Q4）。规则用 2026-10-28 至 11-06 的真实公告和新闻干跑调过（只看标题分级，23 只股票没有误报重大消息）；真实模型解读和飞书推送要部署后才能验证。顺带修了 `get_anns`：它请求的字段名是错的，TuShare 不报错只返回存在的字段，所以数字人一直看不到公告标题。

**内容和原方案一样：**

- **来源：** 交易时段和盘前每 15 分钟、晚上 19:00 至 22:00 每 30 分钟拉持仓和自选的公告；新闻入库时匹配股票。
- **过滤：** 先用规则筛，不调模型；相同内容去重，同一只股票 1 小时内只处理一次，每天最多解读 10 条。
- **处理：** 重要消息由情报官跑短任务，推一句话卡片和链接。
- **推送时间：** 07:30 至 22:30 即时推；停牌、立案这类重大利空随时推。

**改动一处：** 解读结果存成结构化事件（类型、方向、严重程度），由引擎使用。严重事件让这只股票暂停挂单并标“消息待复核”，事件类型也进特征库。模型只解读文字，不直接改价格。

## 8. 风险

- **模型可能跑不赢基线。** A 股日频预测信号很弱，第 5 节的门槛可能过不了。Q3 结束时就能看出苗头，到时候先汇报再决定要不要继续。
- **日线看不出当天先后。** 同一天既碰到卖价又碰到止损价时分不清顺序。需要分钟数据，先确认权限；没有就按不利的情况算。
- **过拟合。** 特征多、样本长，容易在历史上看着好。靠滚动训练、2019 年后只验证、影子运行三道关防住。
- **算力。** 全市场 15 年加上几十个特征，这台机器 9GB 内存偏紧。用 float32 和分年存储处理，训练放线下，线上只跑推理。
- **边界。** 系统不接券商、不自动下单。`CLAUDE.md` 写的“研究、监控、复盘”定位需要客户确认后同步更新，因为挂单已经是具体的操作结论。
