# 研究目标与完成审计

把复杂研究当成一份需要验收的工作，而不是一次尽量写长的回答。目标、标准和证据之间的关系决定任务是否完成。

## 建立目标

1. 用一句话定义研究对象、范围和决策问题。
2. 把用户明确要求转为必选标准，不擅自降低要求。
3. 补充会显著影响可信度的标准，例如数据时点、反方证据、风险和数据缺口。
4. 把“写得全面”改成可检查的结果，例如“覆盖最近一期三张财务报表并标明报告期”。
5. 将执行动作与研究结论分开。这个技能不授权交易，也不替用户作最终投资决策。

## 证据规则

- 标准只能由与其直接相关的证据满足。
- 工具成功不等于证据有效；空结果、错误结果、未来日期、过期数据和无法定位来源的材料不能通过。
- 记录数据来源、数据日期、标的范围、方法、假设和限制。
- 重要结论优先使用原始披露或两个独立来源交叉核验。
- 证据相互冲突时保留冲突，不选择性删除不利证据。
- 文件产物只有在路径、版本、哈希和格式校验均有效时才算交付。

## 研究推进

1. 先检查现有目标和已收集证据，避免重复工作。
2. 优先解决会阻塞多个结论的证据缺口。
3. 长任务按里程碑推进，但不要把一个自然任务机械拆成大量微任务。
4. 委派给多个 Agent 时，一个 Agent 对应一项边界清晰、可以独立验收的任务。
5. 新证据改变结论时，更新结论并说明变化原因。

## 完成状态

- `complete`：所有必选标准都有已验证证据，结论与证据一致。
- `incomplete`：仍缺必选证据，但任务还可以继续。
- `insufficient_evidence`：已做合理检索，仍无法得到可靠证据。
- `blocked`：权限、数据源、审批或外部依赖阻止继续。
- `cancelled`：用户明确终止任务。

不要为了给出一个看似完整的答案而把 `incomplete` 写成 `complete`。

## 最终表达

先给结论和置信边界，再说明关键证据、反方证据、未完成项和下一步。除非用户要求查看审计细节，否则不要把内部台账整段倾倒到回答中。
