# 每日自动研究闭环与进化驾驶舱

2026-09-19 · 产品及技术方案 v1 · 历史技术附录。最新产品规划见 [v2 重新规划](plan-v2.md)。

本稿保留早期技术分析；UI 已改用 ImageGen 静态原型，交付与信息架构以 v2 为准。不启用定时任务、不修改正式策略、不接入真实交易。设计稿数据全部为演示值。

## 一、建议的产品形态

在现有「自动选股」基础上扩展「研究进化」，共用数据、策略版本和研究账本。后台自动完成可重复的研究与检验；前台让负责人知道今天发生了什么、证据是否成熟、哪一步需要决策。

每日更新行情、计算已登记因子、运行现有方案、更新模拟组合与到期评价。候选方案在限定预算内自动产生和验证；历史回测只在数据、代码或配置变化时重算，其他日复用带指纹的证据。未经人类确认，候选不能覆盖正式方案。

三个不能混淆的概念：

- **策略版本**：一次冻结的因子、参数、构建和执行规则。改一个参数也产生新版本。
- **实验**：围绕一个明确假设，对某个策略版本进行检验；有唯一编号、父实验、预登记协议、正负结果。
- **每日运行**：某个交易日执行某个版本形成的一组产物。同一实验可以有很多日运行。

每日任务执行成功，不等于新实验验证成功。今天创建的实验，今天不能产生真实的 60 日前瞻结果。未到期、数据不足、失败、通过必须分别表示。

## 三、每日闭环怎样运行

采用交易日历和依赖条件触发，以下时刻仅为建议窗口，不以「时钟到了」代替「数据就绪」。时区固定 Asia/Shanghai。日运行编号如 `CYCLE-20260918-001`，实验编号如 `EXP-20260918-042`，UUID 为内部主键。

| 阶段 | 自动动作与产物 | 质量门与失败行为 |
| --- | --- | --- |
| 01 数据更新与质检 | 获取日线、每日指标、股票历史状态、行业、复权/公司行动、交易日历和所需财务数据；冻结可见时间与数据版本 | 同日完整度、可用时间、单位、异常价、重复、停牌/退市识别；不通过时冻结新信号与新模拟订单，仍记录估值质量和异常日报 |
| 02 全 A 因子计算 | 对当日应覆盖的 A 股目录计算注册因子，去极值、标准化、中性化规则有版本；输出截面和缺失原因 | 全 A 指应处理全市场，不是对每只股票编造完整值。停牌、新股、缺财务等保留明确原因；单因子失败仅阻断依赖它的方案 |
| 03 自动选股 | 正式、挑战者、影子在同一数据版本上并行打分和施加约束 | 排名由确定性程序决定；入选、合格未入选、不合格三类均落库 |
| 04 原因分析 | 保存因子贡献、约束触发、阈值、原始证据；LLM 基于这些记录解释 | 数值和排名不可由解释模型修改。LLM 失败时保留规则解释并标记报告降级 |
| 05 成本化回测 | 新版本或变更数据重新执行历史回测，未变化版本复用同一指纹产物；输出净值、成交、未成交和成本分解 | 同样本、股票池、资本、基准与费用规则；模型缺少可成交数据则降低可信度或阻断晋级 |
| 06 独立样本外验证 | 先走滚动训练/验证，再对冻结方案运行封存测试；输出检验协议、窗口、试验次数、统计不确定性 | 研究优化器不能读取封存结果反复调参。已公开使用过的窗口不能继续声称是独立留出集 |
| 07 模拟组合更新 | 日终先根据已发生的行情核算原有订单和持仓，再生成次一可交易时段的目标与待执行单 | T 日收盘信号不得按 T 日收盘价无条件成交；每策略独立账本，现金不足、限价不可成交、停牌、交易单位等必须有结果 |
| 08 5/20/60 日评价 | 每天扫描到期 cohort，计算原始信号的 5/20/60 个交易日结果，同时更新连续组合指标 | 未成熟任务只更新已观察天数，不给完整收益或判定；交易日以已落库且完整的行情判定 |
| 09 新旧方案比较 | 同协议对比正式与候选，列出改善、退步、费用和市场阶段差异 | 不同数据版本、时段、资本或基准不直接相减；先构建可比对照运行 |
| 10 保留或淘汰 | 按冻结政策继续观察、保留候选、暂停或退役候选；合格者生成晋级申请 | 自动决策只管理非正式方案。正式方案恶化时触发告警和人工决策，不能被候选自动替换 |
| 11 生成日报 | 输出结构化日报及可读摘要，链接上述全部证据、异常、待成熟任务、待审批和下一步实验 | 即使上游失败也生成「降级/失败日报」，不能消失或显示为全绿；默认站内可查，外部推送单独配置 |

建议日程：15:45 起增量拉取与有界重试；数据就绪后执行确定性链；夜间异步处理较重实验；日报设截止时间，超时产物标记待补充，之后追加修订版而不覆盖原始日报。非交易日不新增交易 cohort，可做历史实验与维护；财务发布日期按实际可见时间处理。

### 跨日恢复与预算

- 幂等键包含交易日、策略版本、数据版本、阶段及协议哈希；重试增加 `attempt_id`，不重复记账或生成订单。
- 阶段状态为 `queued/running/passed/blocked/failed/skipped/waiting_maturity`；保存租约、心跳、错误分类和检查点。
- 用现有调度器做入口，复用持久化 worker 的认领和恢复能力；CPU 因子/回测使用独立进程任务，LLM 解释使用现有 Agent runtime，避免长任务堵塞 API。
- 数据修订产生新快照和补算运行，并记录 `supersedes_run_id`。旧证据与当时发布的结论仍可查询。
- 起步预算示例：每天最多提出 3 个新候选、最多 2 个同时回测、单次 30 分钟、模型 token 和日金额预算可配置。这些是待压测的运维参数，不是统计有效性的门槛。

## 四、数据可用时间与独立验证

### 冻结可重复的输入

每个实验保存 manifest：数据源及授权范围、数据批次/校验和、股票池按日成员、行情复权规则、财务公告及可见时间、行业分类版本、因子代码/方向/处理规则、参数、训练/验证/测试窗口、基准、资本、费用模型、执行模型、Git 提交、未提交补丁哈希、依赖锁文件、随机种子、LLM 服务商/模型标识/实际返回版本、提示词及工具结果原文。

外部 LLM 不保证可按模型名完全复现，因此保存原始请求/响应、模型返回标识和工具证据，重放既有解释与重新生成解释分别存档。不能仅存一个「模型版本」字符串后宣称全部可复现。

股票池必须包含当时可见的成员及后续退市股票，不能使用今天仍存续的股票回测过去。财务因子使用公告可见时间，不使用报告期末时间作为可用时间。价格收益处理分红、拆并股等公司行动；执行价格与复权研究价格分开。

### 三层验证与防止反复窥探

1. **研发层**：按交易日整体分块做 walk-forward，全部股票的同日样本在同一折。标准化、特征选择、权重和超参数只使用本折允许的数据拟合。不能随机打乱股票日样本。
2. **隔离层**：按标签实际起止时间清除跨边界样本，留出 embargo/gap；5/20/60 日标签分别处理，不能仅机械指定一个 gap 就宣称无泄漏。记录每折训练截止、可见时间和实际清除行数。
3. **独立确认层**：预登记后封存一段最终测试集，提交冻结策略哈希和检验预算，由独立验证任务执行。研究优化器不接触测试集逐样本结果。确认结果一旦展示并用于修改，后续子实验需要新的未用区间或真实前瞻观察，不能复用该窗口当「独立测试」。

封存窗口、样本数、基准、主指标、风险约束、最小有意义改善、失败条件、对照方案在看结果前确定。记录全部候选试验，使用预登记的多重检验/序贯检验政策；可增加 DSR 等研究统计，但不能只挑一个好看的显著性指标。重叠 20/60 日标签使用按时间块 bootstrap 等处理相关性，置信区间显示有效样本口径。

历史独立检验与上线后的真实前瞻分开显示。收集满 60 个交易日也不自动等于样本充分；市场阶段、独立窗口数量和误差范围仍可能不足。

## 五、统一评价体系

先固定一个主比较基准与口径，例如业务选定的宽基收益序列；再保留「当日合格池等权、同等执行约束」研究对照。不能临时更换基准让候选变好。基准若是不可直接投资的指数，只作市场对照；不能虚构与策略完全相同的交易费用。

| 维度 | 定义与展示 | 使用限制 |
| --- | --- | --- |
| 净收益与超额收益 | 费用后净值；区间收益与基准区间收益之差以百分点呈现；另列日主动收益序列 | 算术差、几何相对财富不能混写；累计、年化分别标注 |
| 最大回撤 | 净值相对历史峰值最大跌幅，展示负数和对应起止/修复期 | 下跌更深代表退步；不能把 -10%→-12% 当改善 |
| Sharpe | 日净收益减版本化无风险收益，均值/标准差按交易日年化 | 短窗口、零方差和不规则估值返回不可用或样本不足，不用 0 冒充有效值 |
| 信息比率 IR | 日主动收益均值 / 跟踪误差，采用同一周期年化 | 和 ICIR 明确区分，基准时点必须一致 |
| IC / RankIC | 同日合格全截面预测分数与未来收益的 Pearson / Spearman 相关；5/20/60 日分别计算 | 不是仅在入选 Top-N 上计算；显示样本数、覆盖、分布和中性化前后结果 |
| ICIR | IC 时间序列均值 / 标准差，明确是否年化 | 不与组合 IR 共用字段或标签；重叠标签不能按独立样本计算置信区间 |
| 换手 | 单边换手定义为 `0.5 × Σ|成交名义金额| / 调仓前净值`；买入/卖出金额另列 | 首次建仓与资金进出单列。原有「成员替换比例」保留为不同指标 |
| 容量 | 用 ADV、参与率上限、分时可得流动性、冲击成本及成交失败做多资本规模压力测试 | 输出在约束下可承受的资金规模范围与假设；只有日线时标注粗估，不承诺可实际成交 |
| 市场阶段稳定性 | 预先定义趋势×波动阶段，按当时可见基准数据标记；展示每阶段净超额、回撤、IR、IC 和样本量 | 标签规则不能用未来峰谷；没经历某阶段就是证据不足 |
| 判断准确性 | 分开记录方向命中、盈利比例、事实核验等；给出对应分母和观察期限 | 仅为辅助。赚钱不意味着新闻事实正确，判断正确也不意味着策略可盈利 |

短期 cohort 表只给该窗口可解释的收益、回撤、覆盖与方向结果；Sharpe/IR 的主要决策依据来自足够长的连续组合净值。5 日 Sharpe 不与多年回测 Sharpe 混排。

每个比较项均保存正式值、候选值、差值、单位、改善方向、置信区间、样本数、窗口和质量状态。UI 用红涨绿跌表示市场收益，用独立文字「改善/退步/未成熟」表示研究结论，避免回撤颜色语义相反。

## 六、成本化回测与研究模拟组合

使用统一的事件式执行与记账内核，历史回放、前瞻模拟和容量测算共用规则：

- 每个策略版本拥有隔离账户、订单、成交、现金、仓位批次和日终净值，不与个人真实持仓或手工模拟盘混用。
- 收盘信号生成次日目标单；使用当时已经可见的数据及预登记的执行时段。无开盘/分时数据不能凭空补成交价。
- 明确处理交易日、买卖可用数量、交易单位、价格限制、停牌、退市、公司行动、现金与持仓集中度。具体规则按证券类型和生效日期版本化。
- 成本包含佣金及最低费用、买卖方向相关税费、过户等费用、价差/滑点及市场冲击；上线前核实适用规则，配置生效区间，设计稿不硬编码为永远不变的费率。
- 参与率限制下允许部分成交、拒单与延期；保留目标仓位与实际模拟持仓差异。
- 容量评估至少对多档资金规模做同窗口回放；压力测试成交额下降、成本升高和调仓延迟，输出收益衰减与未成交比例。
- 停牌不把持仓删除；按既定估值政策延续估值并标明陈旧度。退市和缺报价不能通过剔除失败股票美化收益。

实现上优先复用现有回测指标、行情适配与 `paper` 的并发思想，新增 `research_paper_*` 账本及研究执行适配器。暂不直接调用现有 `place_order()` 完成自动调仓。

## 七、候选持续迭代与正式方案治理

### 候选如何产生

先从已登记的因子集合、权重、Top-N、调仓间隔、行业约束等有限空间自动迭代，每次明确一个假设和改动。优化器只读允许的研发证据；因子方向、参数与预算受白名单约束。LLM 可提出解释和下一步实验，不直接修改数据库中的正式参数。

失败也产生实验记录。数据失败记为失败，不等同于策略无效；证据不足记为待观察，不等同于被证伪。重复配置和数据指纹命中已有实验时复用产物，仍记录请求和关联。

后续若允许模型生成代码，需要离线沙箱、无网络/无生产凭据、资源限额、依赖白名单、静态检查和可重放执行。初版只支持参数与注册因子的受控迭代。

### 生命周期

`草案 → 研发实验 → 挑战者 → 影子观察 → 待人工晋级 → 正式`

失败、暂停、退役是独立可追溯状态。现有 challenger/shadow 含义迁移时明确：挑战者侧重研究比较，影子为冻结规则的持续前瞻模拟；两者均无正式发布权限。旧正式方案切换后转影子或退役，保留历史，不删除。

### 晋级政策建议

先过数据与执行质量门、独立测试完整性、风险/成本/容量硬约束，再比较净超额及风险调整表现；对有意义的退步必须说明。没有一个任意综合总分可以覆盖硬约束失败。

最短前瞻观察、至少几个有效窗口、最大可接受回撤、容量目标、换手上限及最小收益改善，由负责人在实验前审批并保存为 `policy_version`。UI 里的 60 日观察、容量门槛等是示例，不能作为已验证的通用标准。多市场阶段样本不足时不能显示「全阶段稳定」。

### 正式切换确认入口

审批展示：当前正式与候选版本、修改原因、同口径对比、改善/退步、封存验证结果、未成熟指标、适用资金规模、费用压力测试、风险声明、回退目标和拟生效交易日。

用户输入实验编号和审批意见，并确认已审阅证据。服务端再次检查：权限、完整验证政策、实验哈希、审批证据包哈希、当前正式版本是否仍一致。事务内以比较并交换方式安排次一允许交易日生效；相同请求幂等，竞争审批返回冲突。

自动任务身份只能创建/暂停/退役候选和提交申请，无 `evolution:approve` 权限；正式切换写入由审批服务承担，限制 worker 的数据库写入权限。现有 `/api/automatic-selection/strategies/{id}/promote` 也必须调用相同治理服务，避免从旧入口绕过新门槛。

拒绝、撤回、批准、失效、实际生效和回退全部留审计记录。自动告警不等于自动修改正式策略；故障期间可阻断新模拟订单并生成处置建议。

## 八、证据与「判断正确/错误」

将判断分成可验事实、方向预测、研究假设三类。每条记录包含原文、对象、生成时间、当时证据、指标/阈值、到期时间、判定程序版本与结论。

例：「降低换手可改善 20 日费用后超额」先登记比较条件；到期后在同股票池/同资本/同成本模型下对比，可能得到「换手下降成立，但净超额改善不成立」。不能只给一个成功徽章。

入选与排除的后验评价都保存：入选后表现不佳、被排除后上涨、未成交导致收益偏离。被排除股票的反事实仅作研究诊断，不等同于可执行组合的收益；禁止据此重写当时信号。

证据链接指向快照、因子行、约束、原始行情、回测成交和到期标签。数据错误使原判定失效时追加更正记录并关联旧判定，不静默改写历史。

## 十、建议技术落点与数据契约

保持 FastAPI + MySQL + Vue，复用调度、认证、不可变策略和已有图表体系。研究计算与 API 进程隔离，计算产物带内容哈希存本地对象目录或后续对象存储。

| --- | --- |
| `research_cycles` / `research_cycle_steps` | 交易日、策略集合、数据版本、依赖、状态、attempt、租约、耗时、输入/输出 artifact、降级原因 |
| `research_experiments` | experiment_id、parent_id、strategy_id、hypothesis、change_diff、protocol_id、manifest_hash、状态、创建者类型 |
| `research_validation_protocols` | 预登记窗口、purge/embargo、主指标、阈值、多重检验、样本门槛、测试集访问记录、签署人与冻结时间 |
| `research_artifacts` | 类型、URI、schema_version、内容哈希、生成器版本、时间范围、输入哈希、可见时间、访问范围 |
| `research_evaluation_tasks` / `research_metrics` | cohort、horizon、到期日期、observed_days、样本/覆盖、metric_name/unit/value、窗口、置信区间、不可用原因 |
| `research_comparisons` | baseline/candidate 的版本及 run、可比性校验、各项差值、改善方向、门槛、完整证据包哈希 |

策略、候选行、已有运行和 5/20/60 日表继续作为原有账本；通过外键或逻辑 ID 建立关联，避免复制两套互不一致的排名。旧简化评估标为 `legacy_forward_basket_v1`，新执行器指标使用新协议，不把历史旧值静默重算成新值。

## 十一、分期交付与验收

以下为 1 名后端、1 名量化、1 名前端且数据权限齐备条件下的初步估算，需在数据审计和历史回填压测后调整。

| 阶段 | 交付 | 工程估算 |
| --- | --- | --- |
| A 基础可信链 | 数据可用时间审计、版本协议、实验/运行模型、统一指标字典、可恢复阶段账本；新 UI 先接现有真实产物 | 1–2 周 |
| B 执行与验证 | 全 A 因子增量任务、统一成本与模拟执行、滚动验证/封存测试、容量和市场阶段评价 | 2–3 周 |
| C 闭环与审批 | 5/20/60 到期任务、同口径比较、候选预算迭代、保留/退役、日报、服务端正式切换约束 | 1–2 周 |
| D 验收与影子运行 | 失败恢复、并发与隔离验证；至少连续 5 个交易日自动执行，重试不重复记账；观察质量与耗时 | 工程 1 周，可与 C 部分重叠 |

工程约 5–8 周；若历史股票池、公司行动或财务可见时间数据不可得，需要缩小可验证范围或延长准备。真实 60 日前瞻必须等待足够交易日，不能用回填代替。

必须通过的验收用例：

1. 数据晚到/缺基础指标时不产生「当日正式成功」和新模拟成交，仍有失败或降级日报。
2. 因子任一行能追到原始数据时间与代码版本；新增未来数据不会改变已经冻结的历史信号。
3. 训练/验证边界的重叠标签被正确清除；优化器读取封存测试证据被拒绝并审计。
4. T 日收盘信号不得按同日已知收盘无条件成交；停牌/价格限制/现金不足均有可核对的模拟结果。
5. 重试、服务重启和并发调度不重复下模拟订单、扣费、晋级或生成冲突正式版本。
6. 5/20/60 日未到期不显示完成；缺数据不以 0 填充收益、Sharpe 或 IC。
7. 全量实验可搜索，包括失败、取消、被淘汰的方案；数据修订后原始结论仍可见。
8. 新旧方案必须同口径才能显示差值；回撤、成本等指标的改善方向正确。
9. 自动任务直接调用旧晋升接口、新审批接口或修改正式槽均失败；人工审批在正式版本已变化时返回冲突。
10. 一份日报能反向定位到全部实验、模拟成交、评价和决策，LLM 失败时确定性结果仍完整。

## 十二、方法参考与取舍

- [Qlib 实验记录](https://qlib.readthedocs.io/en/stable/component/recorder.html)：其记录器区分信号分析和组合分析，可借鉴 IC/RankIC、成本后绩效与实验产物组织。这里只作为计算适配器候选，不另建一套正式方案治理系统。
- [Qlib 结果分析](https://qlib.readthedocs.io/en/latest/component/report.html)：可借鉴净值、回撤、换手与 IC 报告；其文档中部分累计口径与本方案的复利净值不同，接入时必须显式转换，不能直接拼表。
- [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)：提供按时间顺序切分和 gap；金融标签区间清除及封存测试治理仍需单独实现。
- [Bailey 与 López de Prado：Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)：解释多次尝试和收益分布为何会放大表面 Sharpe；用于设计试验登记与统计校正，不是给任意策略盈利背书。

需在实施前确定的业务参数：主基准、研究资金规模、风险/容量硬约束、允许的因子族、验证观察长度、审批负责人和模型预算。UI 演示采用的数值仅用于讨论这些参数。
